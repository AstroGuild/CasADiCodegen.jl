Matrix code and functions without instructions

This page explains the two kinds of Julia code that the package generates from a matrix (MX) function of CasADi, and how it generates code for the functions and nodes of CasADi without instructions: an interpolant, an integrator, a rootfinder and others, which CasADi evaluates with its own compiled code instead of a list of instructions that the package could read. It is meant for a reader who chooses between expand = true and expand = false, or who wants to know why a model with an interpolant, an integrator or a rootfinder of CasADi gives Julia code that does not call CasADi.

Expanded code and matrix code

By default a matrix (MX) function is expanded to scalar operations, which gives the fastest code for a model of moderate size but repeats the body of a called function at each call, so a model with many calls of a large function compiles slowly and can run slower (see Cost of the two kinds of code). With expand = false the generated code keeps the matrix operations, and each called function becomes one Julia function that is compiled once. With the default expand = true, the package first asks CasADi to expand the whole function; when the function calls Julia functions at its top level, it expands the operations before, between and after those calls instead, which still gives scalar code (see Call a Julia function from the model); and only when CasADi cannot expand what lies between the calls, or a call of a Julia function is inside a called function, does the code keep the matrix operations.

if_else(c, a, b, true) and conditional(k, cases, default, true) of CasADi, whose last argument short_circuit = true asks for a switch between functions, make code that needs only one branch. Expanded code computes each branch and selects one value, as CasADi does when it expands, while code that keeps the matrix operations runs only the branch that is selected. The package does not choose between the two from the cost of a branch: when CasADi can expand every branch, the default expand = true gives expanded code that computes all of them, so an expensive branch needs expand = false, whereas a branch that CasADi cannot expand, such as a call of a Julia function, keeps the code as matrix code with either setting, because the switch calls each branch as a separate function and a call of a Julia function inside a called function is the last case of the rule above.

g, g! = build_function(f; expression = Val{false}, expand = false)   # f is an MX function

Code that keeps the matrix operations also contains the operations that CasADi cannot expand to scalar code. An index that is a value of the model, as in v[i] with a symbolic i, and the search of an interval in a grid, which a linear interpolant with the option inline uses, become ordinary Julia code, while monitor prints its operand with its text at each call.

Functions and nodes of CasADi without instructions

Some functions and nodes of CasADi have no list of instructions, and CasADi does not give their data through its interface. The package reads that data from two texts that CasADi can write for any function: the C code that CasADi generates, which holds each table and each index list, and the text that serialize gives with the names of the fields, which holds the options of a solver. From that data the package emits Julia code that does not call CasADi and that accepts dual numbers. When it builds the code, the package evaluates it at test points, which are fixed values of the inputs that the package chooses, and compares the results with those of CasADi within a small tolerance. A difference at these points is an error at build time; the check finds a wrong translation at the test points, but it does not prove that the code agrees with CasADi at every input.

Cost of the two kinds of code

The cost of expansion shows in a model that calls one scalar function of 710 instructions 20 times in a chain and returns the result with its Jacobian. Expanded code repeats the 710 instructions at each of the 20 calls, so it takes longer to build and to compile, and in this model it is also slower at later calls than the matrix code, which compiles the called function once; both are faster than the virtual machine of CasADi. The table gives one measurement of each form; the measurement does not record which form of the generated function was called, so its memory column is not comparable with the forms that allocate no memory in Scalar code and its forms.

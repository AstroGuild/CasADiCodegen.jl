Scope and differences from CasADi

This page lists what the package supports, what it refuses when it builds the code, and where the generated code or the front end behaves differently from CasADi or from Julia. It is meant for a reader who checks whether a model fits the package before writing it, or who meets an error at build time; the other pages of the manual link here instead of repeating these lists.

Differences from CasADi

Numbers in a Dict of options

Integer options before version 0.26.0

The Julia front end of CasADi 3.8.1 (CasADiSWIG_jll) gives an integer, or a Float64 with a whole value, in a Dict of options to CasADi as true, that is

  1. Before version 0.26.0, CasADiCodegen.jl passed these values unchanged, so

Dict("number_of_finite_elements" => 7) made an integrator with 1 step, and "max_iter" => 50 allowed 1 iteration, in a nested Dict too. CasADi gave no error, because it accepts true for an integer or a real option. The values 0 and 1 were right by chance; any other whole number, negative too, was 1. A model with such an option gives other numbers from version 0.26.0 on, so any result that came from it must be computed again. The code of the model needs no change, except in the two cases that the end of this section names.

The cause is in the Julia front end of CasADi 3.8.1, which converts a number to the boolean true before it tries an integer or a double; a vector of such numbers becomes a vector of bool, which CasADi refuses with the error "type mismatch", so a vector gave an error and no wrong result. The defect is reported as casadi/casadi#4445, for CasADi 3.8.2. CasADiCodegen.jl converts the Dict before each call of the front end that takes options, so that an integer reaches CasADi as an integer and any other real number as a double, also in a vector and in a nested Dict.

Two cases keep the defect: a value in a Vector{Any} or in another container that is not a Dict, and the module of CasADiSWIGjll used directly, without CasADiCodegen.jl. The first case is avoided with a vector of a concrete element type, such as [1, 2] or Float64[1, 2], and with nested options given as a Dict. The function `changeoption(f, name, value)is not affected: it takes aGenericType` only, and the front end has no way to make one from a number.

Other differences

  • The newton rootfinder does not read the option constraints, because the Newton method of CasADi does not use it.

  • An operation that leaves its domain gives NaN, through NaNMath.jl, as in CasADi; nanmath = false selects the functions of Base, which throw. erfinv is the accurate SpecialFunctions.erfinv, where that of CasADi has a relative error up to 1e-4.

  • Determinant, inverse and linear solve use a dense LU factorization, where CasADi uses a sparse QR factorization, so the results agree to rounding error only, and a singular matrix gives Inf or NaN and no error. A solve with a sparse matrix of 8 rows or more uses the sparse QR factorization of CasADi when its factors have fewer nonzeros than half of the full matrix; for a tridiagonal matrix, measured once:

    RowsSparse QRDense LUCasADi virtual machine
    501.9 µs10.3 µs6.6 µs
    2007.8 µs143.7 µs12.3 µs

  • CasADi 3.8.1 computes a wrong value, read from other memory, for one node: the sum into the nonzeros at a fixed slice plus indices that are values of the model. This node is the reverse derivative of a read such as get_nz(v, false, Slice(1, 5, 2), i), in which the Slice of CasADi counts from 0 and so selects the second and the fourth nonzero. The generated code gives the correct sum, so its result differs there from that of the virtual machine of CasADi, the interpreter with which CasADi evaluates a function on numbers.

  • CasADi 3.8.1 gives an integrator with an event function the sparsity pattern of the model without events, so its Jacobian loses the effect of the transitions, with no error, in the virtual machine of CasADi too. In this package, jacobian(ex, arg) of an expression that calls such an integrator gives the dense Jacobian of one forward direction per element of arg, and the method jacobian() of a Function that holds one throws an error that names jtimes.

  • inv(A) is the matrix inverse for SX and for MX, as in Julia, and inv(A, "qr") names the linear solver of an MX graph. The function CasADiCodegen.C.inv(A) of the front end of CasADi 3.8.1 is the reciprocal of each element for an MX matrix.

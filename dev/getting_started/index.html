Getting started

In this tutorial, we write a small model with CasADi, generate Julia functions for the model and its Jacobian, and call them with ordinary arrays, static arrays and a sparse matrix. We then write the same functions to a file and compare the forms of the generated code and what each one costs. The examples need CasADiCodegen.jl, StaticArrays.jl and the standard library SparseArrays. The file that we write in Write the code to a file also needs StaticArraysCore.jl and NaNMath.jl in the environment.

Write the model

CasADi builds a model from symbols. An SX expression is a graph of scalar operations, an MX expression is a graph of matrix operations and of calls to other functions, and a DM is a matrix of numbers. A Function of CasADi maps a list of inputs to a list of outputs, and CasADi differentiates it from its graph.

using CasADiCodegen loads the official CasADi front end, the SWIG interface that ships with CasADi 3.8.1. Its calls are those of Python, and the CasADi documentation describes them. Four rules apply in Julia:

  • The front end exports the common names: SX, MX, DM, jacobian, gradient, hessian, vertcat, horzcat, substitute and others.
  • Each other function of CasADi is in the module CasADiCodegen.C, for example CasADiCodegen.C.sumsqr and CasADiCodegen.C.nlpsol.
  • CasadiFunction makes a function of CasADi, because a bare Function is the abstract type of Julia. CasADiCodegen.Function is another name for the same type.
  • Elements have the indices of Julia: x[1] is the first one. Methods of CasADi that take an index of an input or an output keep the indices of CasADi, which start at 0.
using CasADiCodegen

x = SX.sym("x", 3)
y = [sin(x[1]) * x[2]; x[3]^2 / (1 + x[1]^2)]
f = CasadiFunction("f", [x], [y, jacobian(y, x)])

We have a function f with one input, the vector x of three elements, and two outputs: the value y and its 2 by 3 Jacobian.

Generate functions for this session

build_function returns a pair: an out-of-place and an in-place function. We ask for compiled functions with expression = Val{false} and call the first one:

g, g! = build_function(f; expression = Val{false})
value, J = g([0.3, 1.7, -0.4])
J
2×3 Matrix{Float64}:
  1.62407    0.29552   0.0
 -0.0808013  0.0      -0.733945

The out-of-place function takes one array per input and returns one array per output. A column is a Vector, any other shape is a Matrix, and a scalar is a vector of one element. With one output the function returns the array itself. Choose a form lists the other forms.

The in-place function takes a tuple of outputs and a tuple of inputs. We give it arrays of the right sizes:

out = (zeros(2), zeros(2, 3))
g!(out, ([0.3, 1.7, -0.4],))
out[1]
2-element Vector{Float64}:
 0.5023843513242772
 0.14678899082568808

Avoid allocation with static arrays

When the first argument is a static array, the out-of-place function returns static arrays and allocates no memory. The example loads StaticArrays.jl itself, because CasADiCodegen.jl does not export its names.

using StaticArrays

value, J = g(SVector(0.3, 1.7, -0.4))
typeof(J)
SMatrix{2, 3, Float64, 6} (alias for StaticArraysCore.SArray{Tuple{2, 3}, Float64, 2, 6})

force_SA = true makes the out-of-place function return static arrays for any argument. The in-place function also accepts MVector and MMatrix.

Fill a sparse Jacobian

The in-place function also fills a SparseMatrixCSC that has the pattern of the output. We make one from the sparsity pattern of the Jacobian with SparseMatrixCSC(sparsity); the function then writes the stored values only, and it rejects a matrix with another pattern.

using SparseArrays

Js = SparseMatrixCSC(CasADiCodegen.C.sparsity_out(f, 1))   # pattern of the second output: CasADi counts from 0
g!((zeros(2), Js), ([0.3, 1.7, -0.4],))
Js
2×3 SparseArrays.SparseMatrixCSC{Float64, Int64} with 4 stored entries:
  1.62407    0.29552    ⋅ 
 -0.0808013   ⋅       -0.733945

A structural zero is an element that the sparsity pattern leaves out. A structural zero of an output is zero, and that of an input is not read.

Write the code to a file

generate_julia writes the functions to one module. For a model such as this one, the module does not need CasADiCodegen.jl to run. We write it to a temporary file and include it:

path = joinpath(mktempdir(), "f.jl")
generate_julia(f, path; module_name = :F)
include(path)
F.f([0.3, 1.7, -0.4])[1]
2-element Vector{Float64}:
 0.5023843513242772
 0.14678899082568808

F.f! is the in-place function, with the arguments of g! above:

F.f!(out, ([0.3, 1.7, -0.4],))
out[2]
2×3 Matrix{Float64}:
  1.62407    0.29552   0.0
 -0.0808013  0.0      -0.733945

The keyword module_name names the module; by default the name is that of f with its first letter in upper case. The module holds F.f, F.f! and F.f_nonzeros! (see Choose a form) and constants that describe the function:

ConstantContent
NAME, NAMES_IN, NAMES_OUTName of the function, and tuples of the names of its inputs and outputs
NNZ_IN, NNZ_OUTTuples of the numbers of structural nonzeros of the inputs and outputs
NWORKLength of the work vector
SPARSITY_IN, SPARSITY_OUTTuples of sparsity patterns, each (nrow, ncol, colptr, rowval) with indices from 1
DEPENDENCIESSorted tuple of the names of the packages that the module imports

The module imports StaticArraysCore.jl for the method with static arrays, NaNMath.jl unless nanmath = false, and SparseArrays.jl whenever an input or an output has structural zeros, as the Jacobian of this model has, even when every caller passes dense arrays; SpecialFunctions.jl, LinearAlgebra and the packages of Julia functions in the model are imported when the code calls them. Each package must be in the environment that loads the file, and a package that includes the file must list the packages of DEPENDENCIES as its own dependencies:

F.DEPENDENCIES
(:NaNMath, :SparseArrays, :StaticArraysCore)

A model with an integrator, a rootfinder or an optimization solver gives a module that also loads CasADiCodegen.jl, SciMLBase.jl and the package of the algorithm.

Choose a form

CallResultNeeds CasADiCodegen.jl to run
build_function(f)An Expr with the definitions, for eval or a macroYes
build_function(f; expression = Val{false})Compiled functions for the current sessionYes
build_function(f; expression = Val{false}, cache = true)The same, compiled once and loaded in later sessionsYes
generate_julia(f, path)A file with one module, for include or for a packageNo, unless the model holds a SciML solver

With nonzeros = true, build_function returns the single function (res, arg) -> res, which evaluates the function as CasADi does. arg[i] is a vector of the structural nonzeros of input i, and the function writes those of output j into the vector res[j]; the nonzeros are in column-major order.

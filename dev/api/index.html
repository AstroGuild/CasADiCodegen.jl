API reference

This page lists the functions and types of CasADiCodegen.jl, grouped by task. The package exports build_function, generate_julia and CasadiFunction, and using CasADiCodegen also gives the names that the front end of CasADi exports, such as SX, MX, jacobian and vertcat. The other names of this page need the prefix CasADiCodegen., except callback, integrator and rootfinder, which are exported functions of the front end to which the package adds methods.

Code generation

CasADiCodegen.CasadiFunction — Type
CasadiFunction(name, inputs, outputs[, options])

Make a function of CasADi from the symbolic inputs and outputs. CasadiFunction is the front end's name for CasADiCodegen.Function, exported because a bare Function is the abstract type of Julia.

x = SX.sym("x", 2)
f = CasadiFunction("f", [x], [sin(x[1]) * x[2]])

CasADiCodegen.Codegen.build_function — Function
build_function(f; expression = Val{true}, force_SA = false, nonzeros = false,
               name = Symbol(name_of_f, "!"), chunk_size = nothing, split_above = nothing,
               nanmath = true, expand = true, cache = false, solvers = nothing, optlevel = nothing)

Generate Julia code for the CasADi function f, in the manner of Symbolics.build_function. Return an out-of-place function g(arg1, arg2, ...) and an in-place function g!(res, arg): as one Expr with the two definitions by default, or as the pair (g, g!) of compiled functions with expression = Val{false}.

Both functions take arrays in matrix shape; a column is a vector.

  • g takes one array per input. It returns one array for one output, and a tuple of arrays otherwise. The arrays are SVector and SMatrix when the first argument is a static array, and Vector and Matrix otherwise.
  • g! fills the arrays of the tuple res from the tuple arg and returns res. An array of res can be a mutable static array.
  • A structural zero of an output is set to zero. A structural zero of an input is not read.
  • With SparseArrays.jl loaded, an array of res or arg can be a SparseMatrixCSC with the sparsity pattern of that output or input, which SparseMatrixCSC(sparsity) makes. g! then reads and writes the stored values only.

f must have no free symbols and only supported operations; see Scope and differences from CasADi.

Keywords

  • expression = Val{true}: Val{true} returns an Expr, and Val{false} returns compiled functions.
  • force_SA = false: with true, g returns static arrays for any argument.
  • nonzeros = false: with true, return the single function (res, arg) -> res on which the others are built. arg[i] holds the structural nonzeros of input i, and res[j] receives those of output j, as CasADi evaluates a function.
  • name: the name of g! in the returned Expr, a valid identifier. It must end with ! unless nonzeros is set. The name of g is name without !.
  • chunk_size = nothing, split_above = nothing: a function with more than split_above instructions is split into sub-functions of at most chunk_size instructions. This shortens the compilation of a large function and costs some speed. chunk_size is 1000 by default. split_above is chunk_size when that is given; otherwise it is 50000 for scalar code and 1000 operations for matrix code. See Large functions and the cache on disk.
  • nanmath = true: an operation outside its domain returns NaN through NaNMath.jl, as in CasADi. With false it throws a DomainError, as in Base, and the code accepts any real number type.
  • expand = true: a matrix (MX) function is expanded to scalar operations where CasADi can do that. With false the code keeps the matrix operations. See Matrix code and functions without instructions.
  • cache = false: with true or a directory, the compiled functions come from a package on disk that Julia compiles once, so a later session compiles nothing. It needs expression = Val{false}. Code that runs already must call the functions with Base.invokelatest. A Julia function in the graph must belong to a package. See Large functions and the cache on disk.
  • optlevel = nothing: with an integer from 0 to 3, Julia compiles the functions at this optimization level, as Base.Experimental.@optlevel sets it, in place of the level of the session (-O, 2 by default). A lower level shortens the compilation at the first call of a large function and can slow the later calls. It needs expression = Val{false}, and with cache it sets the level of the cached package.
  • solvers = nothing: a CasADiCodegen.Solvers with the SciML solvers that the code calls in place of the solver objects of CasADi in the graph. Generated code never calls CasADi, so such an object with no solver throws an ArgumentError.

Examples

julia> using CasADiCodegen

julia> x = SX.sym("x", 2);

julia> f = CasADiCodegen.Function("f", [x], [x[1] * x[2], jacobian(x[1] * x[2], x)]);

julia> g, g! = build_function(f; expression = Val{false});

julia> g([2.0, 3.0])
([6.0], [3.0 2.0])

julia> out = (zeros(1), zeros(1, 2));

julia> g!(out, ([2.0, 3.0],));

julia> out[2]
1×2 Matrix{Float64}:
 3.0  2.0

CasADiCodegen.Codegen.generate_julia — Function
generate_julia(f, path; module_name, force_SA = false, name = Symbol(name_of_f, "!"),
               chunk_size = nothing, split_above = nothing, nanmath = true,
               expand = true, solvers = nothing, optlevel = nothing) -> path
generate_julia(f, io::IO; kwargs...) -> nothing

Write Julia source code for the CasADi function f to the file path or to the stream io, as CasADi generate writes C code. The output is one module with the functions of build_function, which describes them.

The module holds:

  • the in-place function name;
  • the out-of-place function, whose name is name without !;
  • the function on nonzeros, whose name is that name followed by _nonzeros!;
  • the constants NAME, NAMES_IN, NAMES_OUT, NNZ_IN, NNZ_OUT, NWORK, SPARSITY_IN, SPARSITY_OUT and DEPENDENCIES. Each sparsity pattern is (nrow, ncol, colptr, rowval), 1-based. NWORK is the length of the work vector. DEPENDENCIES is the sorted tuple of the names of the packages that the module imports.

The module does not need CasADiCodegen.jl. A package that includes the file must have each package of DEPENDENCIES as a dependency. The module imports:

  • StaticArraysCore.jl, for the method with static arrays, unless f has no input;
  • NaNMath.jl, when the code has an operation with a limited domain, such as sqrt or log, unless nanmath = false;
  • SparseArrays.jl, when an input or an output has structural zeros, as most Jacobians have, for the methods with sparse matrices;
  • SpecialFunctions.jl for erfinv, LinearAlgebra for the factorizations of matrix code, StaticArrays.jl and the package of each Julia function of a callback.

A Julia function of a callback must be a named function of a module. The module calls it by its full name and imports its package.

A function with an integrator, a rootfinder or an optimization solver of the SciML extension gives a module that makes the solvers again. That module loads CasADiCodegen.jl, SciMLBase.jl and the packages of the algorithm, which must be installed.

Keywords

  • module_name: the name of the module, a valid identifier. The default is the name of f with its first letter in upper case.
  • optlevel = nothing: with an integer from 0 to 3, the module sets its optimization level with Base.Experimental.@optlevel.
  • The other keywords of the signature have the meaning that build_function gives them.

Examples

generate_julia(f, "f.jl"; module_name = :F)
include("f.jl")
F.f([2.0, 3.0])         # the out-of-place function

Julia models traced into CasADi

CasADiCodegen.Codegen.Traced — Type
Traced{S}(value::S) <: Real

A real number that records the operations on it as a CasADi expression of type S, which is SX or MX, so that generic Julia code traces into a CasADi graph.

Arithmetic, the elementary functions, min, max, clamp, ifelse and norm give Traced values; a plain number promotes to Traced. A comparison gives a traced condition, not a Bool, so an if, && or ? : on traced values throws a TypeError instead of following one branch. Use ifelse, min, max or clamp for a choice that depends on the input, or CasADiCodegen.callback for a Julia function with branches.

See CasADiCodegen.traced and CasADiCodegen.untraced.

source
CasADiCodegen.Codegen.traced — Function
traced(x::Union{SX,MX}) -> Vector{Traced}

Return the elements of the symbolic column vector x as a vector of CasADiCodegen.Traced, the argument of a generic Julia function to trace.

Examples

using CasADiCodegen, LinearAlgebra

acceleration(r, μ) = -μ * r / norm(r)^3          # generic Julia code
r = SX.sym("r", 3)
a = acceleration(CasADiCodegen.traced(r), 398600.4418)
f = CasadiFunction("a", [r], [CasADiCodegen.untraced(a)])
g, g! = build_function(f; expression = Val{false})

CasADiCodegen.Codegen.untraced — Function
untraced(v) -> SX or MX

Return the CasADi expression of the traced value v, or the column vector of the expressions of the elements of the vector v. A plain number in v becomes a constant.

ifelse(condition::Traced, a, b)

Return the traced selection: a where condition is not zero, else b. Both values stay in the graph, as with CasADi if_else, and the derivative is that of the selected value.

Julia functions inside a model

CasADiCodegen.callback — Method
callback(f, name, sizes_in, sizes_out; jacobian = nothing, options...) -> CasADiCodegen.Function

Make the Julia function f a CasADi function that a matrix (MX) graph can call. Code from build_function and generate_julia calls f and its Jacobian directly, with no CasADi in between.

Arguments

  • f: a function that takes one array per size of sizes_in. It returns one array, or a tuple with one array per size of sizes_out. A result can be any array with the right number of elements, for example a static array.
  • name: the name of the CasADi function, a valid identifier.
  • sizes_in, sizes_out: tuples with one size per argument and per result. A size is an integer n or a tuple (n,) for a vector, which f receives as a Vector, or a tuple (rows, columns) for a matrix.

Keywords

  • jacobian = nothing: how CasADi differentiates f.
    • nothing: no derivative.
    • A Julia function with the arguments of f. It returns the Jacobian matrix, or a tuple with one matrix per pair of result and argument, ordered by result first.
    • A tuple of such functions, for derivatives of higher order. Each function returns the Jacobian blocks of the function before it: one matrix per pair of a block and an argument, ordered by block first. A block counts as the vector of its elements in column-major order.
    • An ADTypes.jl backend, such as AutoForwardDiff(), for any order. Load DifferentiationInterface.jl and the package of the backend.
  • options...: options of CasADi for the function, for example enable_fd = true.

generate_julia needs f and the Jacobian functions to be named functions of a module. See Call a Julia function from the model.

Examples

julia> using CasADiCodegen

julia> square(v) = v .^ 2;

julia> c = callback(square, "square", (2,), (2,); jacobian = v -> [2v[1] 0; 0 2v[2]]);

julia> v = MX.sym("v", 2);

julia> f = CasADiCodegen.Function("f", [v], [c(v), jacobian(c(v), v)]);

julia> g, g! = build_function(f; expression = Val{false});

julia> g([3.0, 4.0])
([9.0, 16.0], [6.0 0.0; 0.0 8.0])

SciML solvers inside a model

integrator and rootfinder are the functions of the CasADi front end. With a solver name such as "cvodes" or "kinsol", they make a solver object of CasADi itself, as in Python. The methods below take a SciML algorithm instead; they exist once SciMLBase.jl is loaded, which each SciML solver package does.

CasADiCodegen.casadi.integrator — Method
integrator(name, alg, dae, t0, tf; specialize, adjoint = false, mass, options...) -> CasADiCodegen.Function
integrator(name, alg, dae, t0, times::AbstractVector; specialize, adjoint = false, options...) -> CasADiCodegen.Function
integrator(name, alg, dae; specialize, adjoint = false, mass, direction = 0, interp_points = 10,
           events = 1, terminal = true, options...) -> CasADiCodegen.Function

Make a CasADi function that integrates an ordinary differential equation with the SciML algorithm alg, for example Vern9() of OrdinaryDiffEqVerner.jl. CasADi differentiates the function to any order, and build_function emits code that calls the solver directly.

The times select the form of the function. p is absent when the model has no parameters.

CallFunctionResult
integrator(name, alg, dae, t0, tf)F(x0, p)the state at tf
integrator(name, alg, dae, t0, times)F(x0, p)a matrix; column k is the state at times[k]
integrator(name, alg, dae)G(x0, p, t0, tf)the state at tf; CasADi also differentiates by the two times

With free times, tf can be before t0 or equal to it. The times of the vector times can be in any order. A model with quadratures returns them as a second result.

Arguments

  • name: the name of the CasADi function, a valid identifier.
  • dae: a dictionary as for the CasADi integrators. It holds the state "x" and its derivative "ode", both dense column vectors. Optional entries are the parameters "p", the time "t" and the integrands "quad". With free times, the entry "zero" is an event function, and "transition" is the state after an event.
  • t0, tf, times: finite times. t0 and tf must be different.

Keywords

  • specialize = SciMLBase.FullSpecialize: the specialization of the SciML problem. With SciMLBase.AutoSpecialize the solver is compiled once for all integrators, and the runs are slower.
  • adjoint = false: with true, a reverse derivative comes from an integrator of the adjoint equations, which runs from the final time back to the initial time. Its cost does not grow with the number of parameters.
  • mass: the diagonal of the mass matrix of a model with algebraic states: 0 for an algebraic state and 1 for the others. The element of "ode" for an algebraic state is the residual of an algebraic equation, and its initial value is a guess. alg must accept a mass matrix, as Rodas5P() of OrdinaryDiffEqRosenbrock.jl does. A vector of times is not supported with it.
  • direction = 0: the change of sign of "zero" that is an event: any with 0, from negative to positive with 1, and from positive to negative with -1.
  • interp_points = 10: the number of points of each step at which the solver looks for the change of sign, besides the end of the step.
  • events = 1: the number of events that the integration passes.
  • terminal = true: the integration ends at the last event. With false it applies the transition there too and goes on to tf.
  • options...: options of the solver, for example abstol, reltol and maxiters.

With an event function, the function returns the state at the event, the quadratures if the model has them, and the event time te as its last result; te is a vector with events more than 1. A zero at the initial time is not an event. A call throws when no event comes before tf.

See Integrate a differential equation and Stop at an event.

Examples

using CasADiCodegen
using OrdinaryDiffEqVerner: Vern9

x, mu = MX.sym("x", 4), MX.sym("mu")
r3 = (x[1]^2 + x[2]^2)^1.5
model = Dict("x" => x, "p" => mu, "ode" => vertcat(x[3], x[4], -mu * x[1] / r3, -mu * x[2] / r3))
F = integrator("F", Vern9(), model, 0.0, 3.0; abstol = 1e-13, reltol = 1e-13)

x0, p = MX.sym("x0", 4), MX.sym("p")
f = CasADiCodegen.Function("f", [x0, p], [F(x0, p), jacobian(F(x0, p), x0)])
source
CasADiCodegen.casadi.rootfinder — Method
rootfinder(name, alg, f; options...) -> CasADiCodegen.Function

Make a CasADi function that solves f(z, p1, p2, ...) = 0 for z with the SciML algorithm alg, for example SimpleNewtonRaphson() of SimpleNonlinearSolve.jl. The function takes a first guess of z and the other arguments of f, and returns the root.

f is a CasADi function with dense arguments. Its first argument z is a column vector that is not empty, and its only result, the residual, has the size of z. name is a valid identifier. The options go to the solver, for example abstol and maxiters.

CasADi differentiates the root to any order by the implicit function theorem. build_function emits code that calls the solver directly. See Solve an equation.

Examples

using CasADiCodegen
using SimpleNonlinearSolve: SimpleNewtonRaphson

E, M, e = SX.sym("E"), SX.sym("M"), SX.sym("e")
kepler = CasADiCodegen.Function("kepler", [E, M, e], [E - e * sin(E) - M])
anomaly = rootfinder("anomaly", SimpleNewtonRaphson(), kepler; abstol = 1e-14)

m, ec = MX.sym("m"), MX.sym("ec")
f = CasADiCodegen.Function("f", [m, ec], [anomaly(m, m, ec)])    # the mean anomaly is the first guess

Solvers of CasADi

CasADiCodegen.Codegen.Solvers — Type
Solvers(; ode = nothing, dae = nothing, nonlinear = nothing, optimization = nothing,
          overrides = ())

Select the SciML solvers that generated code calls in place of the solver objects of CasADi in the graph of a function. Pass the result as the keyword solvers of build_function or generate_julia.

Each field is an algorithm, or a Solver when the algorithm has options.

FieldReplaces
odethe integrator cvodes, and idas without algebraic states
daethe integrator idas with algebraic states
nonlinearthe rootfinders kinsol and fast_newton
optimizationthe solvers of nlpsol and of conic
overridesone object each: a collection of Solver(target, alg; options...)

An override has priority over the other fields. Only an override replaces an integrator rk or collocation or a rootfinder newton, for which the package has Julia code of the method of CasADi. An integrator with an event function is replaced by the same fields, and rk and collocation then need an override.

The tolerances of an integrator of CasADi are the options abstol and reltol of its solver, unless the solver has them. A solver of the first four fields must have no target, and each override must have one. See Replace the solvers of CasADi.

Examples

using CasADiCodegen
using OrdinaryDiffEqVerner: Vern9

solvers = CasADiCodegen.Solvers(ode = CasADiCodegen.Solver(Vern9(); abstol = 1e-13, reltol = 1e-13))
g, g! = build_function(f; expression = Val{false}, expand = false, solvers)   # f calls `cvodes`

Solver(alg; options...)
Solver(target::CasADiCodegen.Function, alg; options...)

A SciML algorithm alg, for example Vern9(), with the options that go to its solver, for example abstol. Use it as a field of Solvers when the algorithm has options.

SciMLBase.ODEProblem — Method
SciMLBase.ODEProblem(I::CasADiCodegen.Function, x0, p = Float64[]; z0 = Float64[], u = Float64[], options...)

Make the SciML problem of the integrator I of CasADi (cvodes, idas, rk or collocation), with generated code for its right side and for the Jacobians of it.

  • The state has the differential states from x0, then the algebraic states from the guess z0, then the quadratures, which start at zero.
  • The parameters are p and then the controls of the current interval. u has one block of controls per output time of I, as for the integrators of CasADi: block k holds from output time k - 1, or from the initial time, to output time k. With more than one block the problem has a callback that changes the controls at each output time.
  • The time span is from the initial time of I to its last output time. The output times are the option saveat, so the solution has one state per output time of I.
  • The tolerances of cvodes and of idas are the options abstol and reltol.
  • With algebraic states the problem has a mass matrix, so it needs a solver for such problems, for example Rodas5P() of OrdinaryDiffEqRosenbrock.jl.

The other options go to the problem, and replace these ones.

An event function gives a callback: when one of its values changes its sign from positive to negative, the state becomes that of the option transition of I. The vectors must have the sizes of I. A callback among the options runs after the one that changes the controls and after that of the events. The callback writes the controls into the parameters of the problem, so do not solve one problem with several intervals from two tasks at the same time. See Replace the solvers of CasADi.

Examples

problem = SciMLBase.ODEProblem(I, [1.0, 0.0, 0.0, 1.0], [1.0])      # I is a `cvodes` integrator
solution = SciMLBase.solve(problem, Vern9(); abstol = 1e-13, reltol = 1e-13)
source
SciMLBase.NonlinearProblem — Method
SciMLBase.NonlinearProblem(R::CasADiCodegen.Function, z0, others...; options...)

Make the SciML problem of the rootfinder R of CasADi (newton, fast_newton or kinsol), with generated code for the residual and for its Jacobian.

z0 is the first guess of the unknown. others are the other arguments of R, in their order, as vectors of their nonzeros; the parameters of the problem are those vectors, joined. The vectors must have the sizes of R. The options go to the problem.

Examples

solution = SciMLBase.solve(problem, SimpleNewtonRaphson())

SciMLBase.OptimizationProblem — Method
SciMLBase.OptimizationProblem(S::CasADiCodegen.Function, x0, p = Float64[]; lbx, ubx, lbg, ubg, options...)

Make the SciML problem of the solver S that nlpsol or conic of CasADi made, with generated code for the objective, the constraints and their derivatives (see OptimizationFunction).

For a solver of conic, the parameters p are the nonzeros of h, then g, then the nonzeros of a, and the constraints g of the bounds are the rows of a.

The bounds have the names and the default values of CasADi: no bound on the unknowns, and none on the constraints. The other options go to the problem. The unknowns must be a column vector, and the vectors must have the sizes of S.

Examples

problem = SciMLBase.OptimizationProblem(S, [0.0, 0.0]; lbg = [1.0], ubg = [1.0])
solution = SciMLBase.solve(problem, Ipopt.Optimizer())              # with OptimizationMOI.jl

Functions of SciML problems

SciMLBase.ODEFunction — Method
SciMLBase.ODEFunction(f::CasADiCodegen.Function; jac = true, paramjac = true, options...)

Make the in-place SciML function of the ordinary differential equation whose right side is the CasADi function f(u), f(u, p) or f(u, p, t). It holds generated code for the right side and for its Jacobians by the state (jac) and by the parameters (paramjac).

f must have one result, a column vector of the size of its first argument. Set jac or paramjac to false to leave that Jacobian out. The other options go to SciMLBase.ODEFunction, for example jac_prototype with a sparse matrix that has the sparsity pattern of the Jacobian. See Give a CasADi function to a SciML problem.

Examples

using CasADiCodegen
import SciMLBase

u, k, t = SX.sym("u", 2), SX.sym("k"), SX.sym("t")
rhs = CasADiCodegen.Function("rhs", [u, k, t], [vertcat(u[2], -k * u[1])])
problem = SciMLBase.ODEProblem(SciMLBase.ODEFunction(rhs), [1.0, 0.0], (0.0, pi), [4.0])

SciMLBase.NonlinearFunction — Method
SciMLBase.NonlinearFunction(f::CasADiCodegen.Function; jac = true, options...)

Make the in-place SciML function of the equations f(u) = 0 or f(u, p) = 0, where f is a CasADi function. It holds generated code for the residual and for its Jacobian (jac).

f must have one result, a column vector of the size of its first argument. Set jac = false to leave the Jacobian out. The other options go to SciMLBase.NonlinearFunction.

Examples

residual = CasADiCodegen.Function("r", [z, q], [equations])
problem = SciMLBase.NonlinearProblem(SciMLBase.NonlinearFunction(residual), z0, q0)
source
SciMLBase.OptimizationFunction — Method
SciMLBase.OptimizationFunction(objective::CasADiCodegen.Function, constraints = nothing; options...)

Make the SciML function of an optimization problem from the CasADi functions objective(x) or objective(x, p) and, if the problem has them, constraints with the same arguments.

The result holds generated code for the objective, its gradient (grad) and its Hessian (hess). With constraints it also holds cons, their Jacobian cons_j, and cons_h(H, x, p), where H has one matrix per constraint. The matrices are dense. The other options go to SciMLBase.OptimizationFunction.

x must be a column vector, and the objective one number. The constraints must be a column vector. The result has no Hessian of the Lagrange function (lag_h): the solvers of Optimization.jl make it from hess and cons_h.

Examples

x = SX.sym("x", 2)
objective = CasADiCodegen.Function("cost", [x], [(x[1] - 1)^2 + x[2]^2])
constraints = CasADiCodegen.Function("cons", [x], [x[1] + x[2]])
f = SciMLBase.OptimizationFunction(objective, constraints)
problem = SciMLBase.OptimizationProblem(f, [0.0, 0.0]; lcons = [1.0], ucons = [1.0])

Automatic differentiation rules and sparse matrices

CasADiCodegen.Codegen.differentiable — Function
differentiable(f::CasADiCodegen.Function; options...) -> Differentiable

Make the CasADi function f a Julia function with forward and reverse rules for ChainRulesCore.jl. A package for automatic differentiation that reads those rules, such as Zygote.jl, then takes the derivatives of f from code that CasADi generates.

The result d takes one array per input of f and returns one array per output, as the out-of-place function of build_function. The options go to build_function.

The rules load with ChainRulesCore.jl. The code of each derivative is generated at its first use. See Use the generated derivatives from an AD package.

Examples

julia> using CasADiCodegen

julia> x = SX.sym("x", 2);

julia> f = CasADiCodegen.Function("f", [x], [x[1] * sin(x[2])]);

julia> d = CasADiCodegen.differentiable(f)
the differentiable function "f"

julia> d([2.0, pi / 2])
1-element Vector{Float64}:
 2.0

SparseArrays.SparseMatrixCSC — Method
SparseMatrixCSC(sparsity::CasADiCodegen.Sparsity) -> SparseMatrixCSC{Float64,Int}

Make a sparse matrix of stored zeros with the sparsity pattern sparsity. Use it as an output or an input of the in-place function of build_function or generate_julia, which then reads and writes the stored values only.

Examples

using CasADiCodegen, SparseArrays

x = SX.sym("x", 2)
f = CasADiCodegen.Function("f", [x], [jacobian([x[1]^2; x[1] * x[2]], x)])
J = SparseMatrixCSC(CasADiCodegen.sparsity_out(f, 0))      # 2×2 with 3 stored entries
_, g! = build_function(f; expression = Val{false})
g!((J,), ([2.0, 3.0],))                             # J is now [4.0 0.0; 3.0 2.0]

CasADiCodegen.Codegen.instruction_histogram — Function
instruction_histogram(f; expand = true) -> Vector{Pair{Symbol,Int}}

Count the instructions of the code that build_function emits for the CasADi function f, by operation. Return the pairs operation => count, the most frequent first.

Matrix code counts the instructions of f itself, not those of the functions that it calls. expand is that of build_function.

Examples

julia> using CasADiCodegen

julia> x = SX.sym("x", 2);

julia> f = CasADiCodegen.Function("f", [x], [sin(x[1]) * x[2] + x[1] * x[2]]);

julia> CasADiCodegen.instruction_histogram(f)
5-element Vector{Pair{Symbol, Int64}}:
  :OP_INPUT => 2
    :OP_MUL => 2
    :OP_ADD => 1
 :OP_OUTPUT => 1
    :OP_SIN => 1

CasADiCodegen.Codegen.nan_trace — Function
nan_trace(f, arguments...) -> NamedTuple or nothing

Find where the first NaN appears when the CasADi function f runs on numbers. Return the first instruction of the scalar code of f whose result is NaN while no operand is, or the first NaN among the arguments. Return nothing when there is no NaN.

Give one argument per input: an array with the shape of the input, or the vector of its structural nonzeros. CasADi must be able to expand f to scalar code, so f cannot call a Julia function.

The result has these fields:

  • instruction: the place of the instruction in the scalar code.
  • operation: the operation, for example :OP_SQRT.
  • operands: the values of the operands.
  • result: the result of the operation.
  • text: the operation on those values, or the place of the NaN in the arguments.

Examples

julia> using CasADiCodegen

julia> x = SX.sym("x", 2);

julia> f = CasADiCodegen.Function("f", [x], [sqrt(x[1]) + x[2]]);

julia> CasADiCodegen.nan_trace(f, [-1.0, 2.0])
(instruction = 2, operation = :OP_SQRT, operands = (-1.0,), result = NaN, text = "NaNMath.sqrt(-1.0)")

julia> CasADiCodegen.nan_trace(f, [1.0, 2.0]) === nothing
true

Stop at an event

An integration can end where a function of the state changes its sign, for example at an apsis of an orbit or at the contact of a ball with the ground, and it can apply a jump of the state there. This page continues Integrate a differential equation and uses its model x, mu, ode and its symbols x0, p, t0, tf.

Find one event

With free times, the entry "zero" of the dictionary holds an event function of the state, the parameters and the time. The integration ends at the event: the first time te between the initial time and tf at which the event function changes its sign.

  • The function returns the state at the event, the quadratures if the model has them, and te.
  • A zero at the initial time is not an event, so an integration can start on the surface.
  • A call throws an error when no event comes before tf, and also when fewer events come than the keyword events asks for.

We compute the time from one apsis of an orbit to the next one, where the radial speed is zero:

apsis = integrator("apsis", Vern9(), Dict("x" => x, "p" => mu, "ode" => ode, "zero" => x[1] * x[3] + x[2] * x[4]);
                   abstol = 1e-12, reltol = 1e-12)
xe, te = apsis(x0, p, t0, tf)
f = CasadiFunction("f", [x0, p, t0, tf], [xe, te, jacobian(xe, x0), jacobian(te, x0)])

Each call runs two integrations: one that finds the event, and one to the event time, with the sensitivities when a result needs a derivative. CasADi differentiates the event time by the implicit function theorem, as the root of the event function, and the state at the event as the result of an integrator with free times, both to any order. The integrator also takes dual numbers, for example when ForwardDiff.jl differentiates the generated code.

Three keywords control the search:

KeywordDefaultEffect
direction0The change of sign: 1 from negative to positive, -1 the opposite, 0 both
interp_points10, as in SciMLThe number of points of each step, besides its end, at which the solver looks for the change; 0 is faster, but can miss two changes of sign in one step
specializeSciMLBase.FullSpecializeWith SciMLBase.AutoSpecialize, after import SciMLBase, the solver compiles once for all event functions

The default direction = 0 differs from the integrators of CasADi, which find a change from positive to negative only.

Pass several events

One integrator can also pass several events, which is how a model applies an impulse or a bounce. The keyword events gives their number (1 by default), and te is then the vector of their times. The entry "transition" of the dictionary gives the state after an event as an expression of the state before it, the parameters and the time. By default, terminal = true ends the integration at the last event. With terminal = false, the integration applies the transition there too and continues to tf, so the result is the state at the final time. CasADi differentiates the result through each event to any order.

We model a ball that falls and bounces three times. Its state is the height and the speed, and its parameters are the gravity and the part of the speed that a bounce keeps:

s, c = MX.sym("s", 2), MX.sym("c", 2)                    # s = [height, speed], c = [gravity, restitution]
ball = Dict("x" => s, "p" => c, "ode" => vertcat(s[2], -c[1]), "zero" => s[1],
            "transition" => vertcat(s[1], -c[2] * s[2]))  # the speed changes its sign and loses a part
bounce = integrator("bounce", Vern9(), ball; events = 3, terminal = false, direction = -1)

s0, c0 = MX.sym("s0", 2), MX.sym("c0", 2)
sf, te = bounce(s0, c0, t0, tf)                           # te has the three times of contact

An integrator of CasADi with an event function and the option "transition" has its own rules. Integrators with events shows how generated code replaces it.
